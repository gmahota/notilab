## 2026-07-13 — AI-first governance bootstrap

- **Decision**: Adopt a tool-agnostic `AGENTS.md` at repo root as the top authority for Claude Code, GitHub Copilot, and Codex, with tool-specific files (`CLAUDE.md`, `.github/copilot-instructions.md`) beneath it in authority order.
- **Decision**: Standardize on **pnpm** as the package manager everywhere (CI, Copilot instructions, and now `AGENTS.md`/`README.md`) — `README.md` previously drifted to `npm`.
- **Decision**: 11 Claude Code subagents (`00-orchestrator` through `10-docs-memory`), split into plan-only (00–02, architecture/risk/domain-meaning) and execution (03–10, can edit), mirroring the split used by the Cash-Flow reference project but with a NotiLab-specific domain roster (editorial-content, integrations-social, ai-pipeline in place of finance-specific agents).
- **Decision**: Quality gate is scoped to what's actually enforced today — ESLint (`pnpm lint`), TypeScript (`pnpm typecheck`), Next.js build (`pnpm build`), plus the existing `security.yml` scans (CodeQL, `pnpm audit`, secret scanning). No new test framework, duplication checker, or pre-push hook was added — those are documented as Phase 2, not built now, to avoid introducing infrastructure the team hasn't asked for.
- **Decision**: Roadmap (`docs/manager/roadmap/ROADMAP.md`) and daily reports (`docs/manager/daily-reports/`) are hand-maintained from templates, not auto-generated from git history or task-spec frontmatter — deferred until there's enough task volume to justify a generator script.
- **Decision**: No `.github/agents/*.agent.md` Copilot persona files were added, to avoid the copy-paste drift risk observed in the reference project's version of these files. Copilot governance is `.github/copilot-instructions.md` + the existing 3 prompt files (`code-review`, `cto-review`, `security-review`).

## 2026-07-15 — `/now` immersive feed redesign (hifi prototype implementation)

Redesigned the `/now` immersive feed end-to-end to match `docs/cto/task/1. V01 - New Layout/designs/Agora - Bandeja.dc.html`. New/changed: `app/api/categories/route.ts`, `lib/immersive/bandeja-store.ts`, `lib/immersive/pace.ts`, `components/immersive/onboarding-bandeja.tsx`, `components/immersive/bandeja-overlay.tsx`, redesigned `story-card.tsx`/`story-feed.tsx`/`immersive-nav.tsx`/`story-context-panel.tsx`/`spatial-story-viewer.tsx`. Verified via `pnpm typecheck` + `pnpm lint` and live browser exercise of every flow (onboarding, category persistence, bandeja overlay open/select/restore, category refetch, why-popover, context panel). **No automated test suite covers this area** — say so explicitly, don't imply coverage exists.

- **Decision**: Client-side personalization state (`followed`/`hidden`/`pace`/`onboarded` categories) for `/now` uses a hand-rolled `useSyncExternalStore` singleton (`lib/immersive/bandeja-store.ts`, localStorage key `notilab:bandeja:v1`) instead of adding a state-management library (zustand, jotai, etc.). Reasoning: this is a small, single-feature client store; React 19 already ships `useSyncExternalStore`, so no new dependency was justified. If a second feature needs similar cross-component client state, extend or generalize this pattern before reaching for a library.
- **Decision**: Switching the active category filter in the immersive feed re-fetches from `/api/news/feed?category=slug` starting at offset 0, rather than client-side reordering an already-loaded page. Reordering paginated infinite-scroll results in place was deliberately avoided — it breaks scroll position/index stability. Similarly, `hidden[]` categories are filtered out client-side from whatever's currently loaded, but "followed-first" reordering of the default ranked feed was explicitly NOT implemented, for the same reason (would require reordering an already-paginated list).
- **Decision**: The design prototype (`Agora - Bandeja.dc.html`) contains fabricated demo data not backed by the schema — multi-source lists, per-article "facts", a "place"/location field, a hardcoded 3D scene. Policy applied: only real backend fields are surfaced. Fabricated fields were either dropped (no location field added), adapted to a real equivalent (the design's "facts" grid → real `stats.reactions`/`stats.reads`/`stats.saves`/`readTime`; "sources" section → the one real `sourceName` field, not the mockup's fake multi-source list), or deferred as explicit, dormant, optional scaffolding (see next decision) — never faked to match the visual design. This is the general policy for any future hifi-prototype implementation: match the prototype's UI, not its placeholder data.
- **Decision**: Added `spatialAsset?: SpatialAsset` (optional) to `FeedArticle`/`ArticleDetail` in `components/immersive/types.ts` as forward-looking, intentionally dormant scaffolding for the design's "Entrar na cena" spatial/3D viewer (`components/immersive/spatial-story-viewer.tsx`, fully built). No production article populates `spatialAsset` yet, so the button never renders. Real backend support (schema/data work on `DailyEdition`/`Story` models, cron changes to populate it) is deferred, out of scope for this pass, and tracked on the roadmap as future work — do not backfill fake `spatialAsset` data to "activate" the viewer without that backend work landing first.
- **Decision (scope)**: The "Explorar" mural redesign (separate design file `Explorar - Mural.dc.html`) and any Prisma schema/migration work implied by the prototype (categories model changes, `reasons`/`facts`/`sources`/`spatialAsset` backend support) were deliberately not touched in this pass — not requested, and schema changes are High/Critical classification per `CLAUDE.md`'s Task Classification Rules, warranting their own dedicated task.
- **Note**: `pnpm build` currently fails on this machine with a `WasmHash`/webpack error. Confirmed via `git stash` that this reproduces identically on unmodified `main` — a pre-existing Node v24.17.0 + webpack incompatibility unrelated to this work, not a regression. `pnpm typecheck`/`pnpm lint` are clean relative to the pre-existing baseline (5 unrelated pre-existing typecheck errors in `share-panel.tsx`/`experiment-results.ts`/`experiments.ts`, one unrelated pre-existing lint warning — not introduced or fixed by this change).
