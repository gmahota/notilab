Append-only log of durable decisions. If a decision is later superseded, add a new entry noting the change — don't edit or delete the old one.

## 2026-07-13 — AI-first governance bootstrap

- **Decision**: Adopt a tool-agnostic `AGENTS.md` at repo root as the top authority for Claude Code, GitHub Copilot, and Codex, with tool-specific files (`CLAUDE.md`, `.github/copilot-instructions.md`) beneath it in authority order.
- **Decision**: Standardize on **pnpm** as the package manager everywhere (CI, Copilot instructions, and now `AGENTS.md`/`README.md`) — `README.md` previously drifted to `npm`.
- **Decision**: 11 Claude Code subagents (`00-orchestrator` through `10-docs-memory`), split into plan-only (00–02, architecture/risk/domain-meaning) and execution (03–10, can edit), mirroring the split used by the Cash-Flow reference project but with a NotiLab-specific domain roster (editorial-content, integrations-social, ai-pipeline in place of finance-specific agents).
- **Decision**: Quality gate is scoped to what's actually enforced today — ESLint (`pnpm lint`), TypeScript (`pnpm typecheck`), Next.js build (`pnpm build`), plus the existing `security.yml` scans (CodeQL, `pnpm audit`, secret scanning). No new test framework, duplication checker, or pre-push hook was added — those are documented as Phase 2, not built now, to avoid introducing infrastructure the team hasn't asked for.
- **Decision**: Roadmap (`docs/manager/roadmap/ROADMAP.md`) and daily reports (`docs/manager/daily-reports/`) are hand-maintained from templates, not auto-generated from git history or task-spec frontmatter — deferred until there's enough task volume to justify a generator script.
- **Decision**: No `.github/agents/*.agent.md` Copilot persona files were added, to avoid the copy-paste drift risk observed in the reference project's version of these files. Copilot governance is `.github/copilot-instructions.md` + the existing 3 prompt files (`code-review`, `cto-review`, `security-review`).

## 2026-08-19 — NOW V2: Story layer, Sprints 1 + 2

Implements the "NotiLab NOW V2" product spec. Sprints 1 (UX) and 2 (schema) only; 3–5 are on the roadmap (#24–#27).

- **Decision**: `/now` is a feed of **events**, not articles. A `Story` holds many `StorySource` rows, so five wire reports of one happening become one card. `News` is unchanged and still backs `/feed`, the homepage, `/trending` and `/news/[id]` — this is an addition, not a migration of those surfaces.
- **Decision**: one read model (`lib/story-view.ts`), two possible origins, chosen in exactly one place (`lib/story-service.ts`). The Story tables when populated, `News` + `ArticleAI` derived otherwise. This is what let Sprint 1's UX ship on today's data instead of waiting for the whole ingestion pipeline to be rewritten, and it means the UI does not change when clustering lands — the same cards just get more sources and more filled-in fields.
- **Decision**: the `story_model` migration is **additive only** — two enums, five tables, two nullable columns, no `DROP`, nothing existing made `NOT NULL`. It was generated offline with `prisma migrate diff --from-schema-datamodel` against the committed schema, precisely so that producing it required no connection to a live database. **It was written but deliberately not applied**: local `.env` and the deployment point at one Neon database (see `lessons-learned.md`), so applying it is a production change and a human's call. Roadmap #23 tracks it.
- **Decision**: never claim a status we have not assessed. `Story.status` defaults to `DEVELOPING`, but `story-service.ts` returns `null` for any story with a single source that has never been revised, and the UI renders no badge for `null`. A "DEVELOPING" pill on every card would be a fabricated signal, which is worse than no signal.
- **Decision**: `confidenceScore` stays internal and is never rendered as a number (spec § 18). `0` means "not assessed", not "no confidence".
- **Decision**: NOW analytics are attributed to `storyId`, not `articleId` — a Story can span several articles, so crediting one of them would misreport what the user saw. Ten `story_*` events added (spec § 35).
- **Decision**: NOW saves live in `localStorage`, because `SavedArticle` needs a `userId` and this surface has no sign-in. The limitation is stated to the user on `/saved` rather than hidden. V1's per-article keys are migrated into the new list on first load so nobody loses their saves. Roadmap #28.
- **Decision**: `Following` is rendered but disabled, with the reason in its tooltip, and `getNowFeed` serves the lane empty rather than aliasing it to "For You". A lane that silently shows unfollowed content is worse than one that says it is not built.
- **Decision**: story-scoped NotiBot pins retrieval to that story's own sources (`retrieveStoryContext`) instead of keyword-guessing, and adds the § 24 instruction requiring FACT / CONTEXT / ANALYSIS / UNKNOWN to be kept apart. General `/api/chat` behaviour is unchanged — the addendum only applies when a `storyId` is supplied.
- **Decision**: a second, story-specific ranker (`lib/story-ranking.ts`) rather than extending `lib/ranking.ts`. That engine ranks articles and feeds `News.rankingScore` using dimensions a story does not have (per-article source trust, trending-tag overlap). Shared conventions — 0–100 dimensions, 24h recency half-life, neutral-50 affinity for anonymous visitors — are kept identical on purpose. Diversity (§ 34) is implemented as greedy selection, because a story's diversity score depends on what has already been placed.
- **Decision**: `/now` copy is English ("Understand in 30 sec", "Why it matters", "You're caught up.") while the rest of the app remains Portuguese, per the product owner's explicit choice. Note that *topic* labels stay Portuguese because they come from `Category.name` — data, not copy.
- **Removed**: `components/immersive/*` and the `/now/{perto,explorar,seguir}` stub routes. All three were `ComingSoon` placeholders for geolocation data the schema still lacks, § 7 drops them from the navigation, and as static children of `/now` they would have shadowed any story slug of the same name.
