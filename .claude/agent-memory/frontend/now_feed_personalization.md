Multi-phase redesign of the `/now` immersive feed to match a hifi prototype. Later phases (separate agent calls) build directly on this API — do not casually rename/reshape it without checking who else consumes it first.

## Phase 1 — personalization foundation

- `lib/immersive/pace.ts` — exports `PaceKey` (`'dinamico' | 'equilibrado' | 'calmo'`), `PACE_ORDER` (added phase 2, cycle order for the pace button), and `PACE_DEFS` (label/desc/cine/titleSize/teaserSize/longTeaser/icon per pace). Framework-agnostic on purpose — no lucide import in this file; consumers map `icon` (plain string) to a lucide component themselves.
- `lib/immersive/bandeja-store.ts` — dependency-free `useSyncExternalStore` singleton (no zustand in this repo, and [[no-state-lib-policy]] says don't add one). Hook `useBandejaStore()` returns `{ followed, hidden, pace, onboarded, hydrated, setPace, setFollowed, toggleHidden, restoreHidden, completeOnboarding, skipOnboarding }`. Persists to `localStorage['notilab:bandeja:v1']`. Server snapshot defaults `onboarded: true` deliberately so nothing onboarding-related renders until the client re-checks localStorage — avoids an SSR/CSR mismatch flash. Hydration happens exactly once (module-level guard), triggered from the hook's `useEffect`, no matter how many components call the hook.
- `components/immersive/onboarding-bandeja.tsx` — self-gating full-screen overlay (`z-[60]`), renders `null` unless `hydrated && !onboarded`. Fetches `GET /api/categories` client-side; renders nothing on fetch failure or zero categories (progressive enhancement, not critical path).
- Mounted in `app/now/page.tsx` alongside `<StoryFeed />` / `<ImmersiveNav />` as a one-line `<OnboardingBandeja />` addition — self-gating, no prop wiring needed.

**Why:** the ask was explicit that the store's public API had to be exact since future phases (feed/card reading `followed`/`hidden`/`pace`, nav settings, etc.) depend on it verbatim.

**How to apply:** if a later phase needs to read/write bandeja state (followed categories, hidden categories, pace, onboarding status), use `useBandejaStore()` as-is rather than inventing a parallel mechanism. If the shape needs to change, update this memory and confirm nothing else already relies on the old shape.

## Phase 2 — feed/card/nav redesign

- `components/immersive/story-feed.tsx` now owns `trayOpen: boolean` and `filter: { slug; name; color } | 'parasi'` (exported as `FeedFilter`), lifted for the not-yet-built `BandejaOverlay` (phase 3). **Prop contract phase 3 must match**: `onSelectFilter(cat: { slug; name; color } | 'parasi')` → calls `setFilter(cat)` + closes tray; `onClose()` → `setTrayOpen(false)`. Mount point is a JSX comment at the bottom of `StoryFeed`'s return marking exactly where `{trayOpen && <BandejaOverlay ... />}` goes.
- Picking a category filter (once phase 3 wires `setFilter`) always refetches `GET /api/news/feed?category={slug}&limit=&offset=0` fresh and resets pagination/index — no client-side reordering of the ranked feed. `hidden[]` categories are excluded via a separate `useMemo` (`visibleArticles`) applied on top of whatever's loaded, independent of the active filter. All index/nav/drag/dots logic operates on `visibleArticles`, not the raw fetched `articles` array — pagination offset/`hasMore` still track the raw fetch.
- "Porque vejo isto?" popover is a fully local feature (no backend/schema change) — pure reason list computed in `story-card.tsx`'s `getWhyReasons(article, followed)`: trending → "Em alta agora", `priority === 'URGENT'` → "Notícia urgente", followed category → "Segues o tema {name}", else fallback "Fonte: {sourceName}". Capped at 3.
- Deliberately did **not** add `icon` to the feed API's category `select` clause (even though the task allowed it) — touching `app/api/**` beyond calling it is out of scope for this agent's lane per its own operating rules, and the task explicitly offered a no-touch fallback. Used a generic `Newspaper` lucide glyph for the text-mode watermark instead. If a later phase wants the real per-category icon here, that's a `04-backend-api` change (additive `select: { icon: true }` in `app/api/news/feed/route.ts` + `app/api/news/[id]/route.ts`, plus `icon?: string` on `FeedCategory` in `components/immersive/types.ts`), not something this agent should do itself.
- No toast library exists in this repo (no `sonner`, no custom hook) — built a minimal local one in `story-feed.tsx` (`{ message, key }` state + `setTimeout` clear ~2.4s). Positioning wrapper (`absolute inset-x-0 flex justify-center`, centering via flex not translateX) is a separate DOM node from the `motion.div` that gets the entrance animation, per the task's explicit warning about combining centering + entrance transforms on the same element.
- `components/ui/popover.tsx` (shadcn primitive) still doesn't exist in this repo (same gap noted in [[project-baseline-typecheck]] re: `share-panel.tsx`) — the why-popover was built as a plain local `useState` + outside-click-listener panel instead of pulling in Radix popover, to avoid expanding scope into a shared `components/ui/` primitive during a feed-specific task.
- `components/immersive/immersive-nav.tsx` was changed from a responsive mobile-bottom-bar/desktop-left-sidebar hybrid to a single floating centered pill on all breakpoints, and the 6th "Em Alta" nav item was dropped (5 items only: Agora/Perto/Explorar/Seguir/Perfil) to match the design's fidelity mandate. `components/immersive/coming-soon.tsx` (shared by `/now/perto`, `/now/explorar`, `/now/seguir`) had its `md:pl-28` (leftover space for the old desktop sidebar) removed since the nav no longer reserves a left gutter on any breakpoint.
- Horizontal swipe-to-open-context gesture was skipped (stretch/optional per the task) — the vertical `drag="y"` paging stayed untouched, "Ver contexto" button is still the only way to open the context panel.

## Phase 4 — context panel (`components/immersive/story-context-panel.tsx`) restyle

- Restyled only; data-fetching/status states (`idle/loading/ready/notfound/error`), `side` prop, `onSelectRelated` callback all untouched. "Porque vejo isto?" popover lives in `story-card.tsx` (phase 2) — not this file.
- Facts grid is real data, not the design mock's fabricated per-article facts: `stats.reactions/reads/saves` + `readTime` (min). Sources section is a single real row (`sourceName`/`sourceUrl`/`publishedAt`), labeled "Fontes (1)" — always singular since `ArticleDetail` only ever has one source, no fabricated multi-source list.
- **The shadcn `Sheet`'s enter/exit transition IS tunable via plain Tailwind classes** — confirmed by reading `tw-animate-css`'s compiled CSS: `animate-in`/`animate-out` (which drive `data-[state=open]:slide-in-from-*` etc.) resolve to `animation: … var(--tw-duration,.15s) var(--tw-ease,ease) …`, and `--tw-duration`/`--tw-ease` are the *same* CSS custom properties written by ordinary `duration-*`/`ease-*` utilities. So overriding `sheetVariants`' baked-in `data-[state=closed]:duration-300 data-[state=open]:duration-400 ease-in-out` just means passing `data-[state=open]:duration-[550ms] data-[state=closed]:duration-[550ms] ease-[cubic-bezier(...)]` via `className` on `SheetContent` (last-wins through `cn`/`twMerge` on the same utility group+variant). No need to fork the primitive or fight it with inline styles. Applies to any `Sheet`/`Dialog`-family Radix primitive in this repo using the same `tw-animate-css` setup.
- Built a custom 34×34 circular close button (`SheetClose` + `showCloseButton={false}` on `SheetContent`) instead of the primitive's default top-4/right-4 `bg-black/30` one, positioned as an always-rendered sibling (not gated on `status === "ready"`) so loading/error/notfound states remain closable.
- Green "verified" check icon color reuses the existing brand neon-green `#39FF14` (same token as `trending`/`glow-green-sm` elsewhere in the immersive UI), not a generic Tailwind green, to stay consistent with the rest of the feed's palette.
